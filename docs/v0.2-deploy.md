# v0.2 Deployment Guide (cut-019 + cut-020)

This document covers v0.2 deployment hardening: multi-tenant (cross-org)
isolation, multi-tenant perf bench, and full v0.2 cut-over checklist.

## 1. v0.2 deployment features (cut-019 + cut-020)

- **Multi-tenant (cut-019)**: `ECE_USER_ORGS` env configures
  `user_ref → org_id` mapping; /audit + /debug require `X-Org-Id`
  header matching trace's recorded org_id; cross-org access blocked
  with 403.
- **Multi-tenant perf bench (cut-020)**: 200-query bench across 2 orgs,
  p95 ≤ 1.5s SLA per ADR-009, plus 100% cross-org denial rate
  verification.
- **v0.2 cut-over gate (cut-020)**: combined E6 ≥80% accuracy + multi-
  tenant perf + cross-org denial acceptance via
  `scripts/bench_e6_real_llm_multi_tenant.sh`.

## 2. Multi-tenant config (cut-019)

```bash
export ECE_USER_ORGS="alice:org_a;bob:org_b;carol:org_a;dan:org_b"
```

Format: `user_ref:org_id;...` — semicolon-separated entries, each
mapping a user to one org.

**When `ECE_USER_ORGS` is unset** (v0.1 single-tenant default):
- `/audit` + `/debug` skip org checks entirely
- `X-Org-Id` header is silently ignored
- Back-compat for v0.1 deployments

**When `ECE_USER_ORGS` is set** (v0.2 multi-tenant):
- `X-Org-Id` header required on `/audit` + `/debug` calls
- `X-Org-Id` must equal trace's recorded `org_id`, else `403`
- `assemble_context` records `org_id` in `context_requests.org_id`
  column (migration 0007_user_orgs)

**Cross-org delegation (cut-021)**: ✅ wired via `ECE_DELEGATION_ORG_TOKENS`.

```bash
export ECE_DELEGATION_ORG_TOKENS="manager_tok:org_a,org_b;audit_tok:*"
```

Format: `token:org_id1,org_id2;token2:org_id3`. Wildcard `*` grants
cross-ALL-orgs access (audit role).

`X-Delegation-Token: manager_tok` on /audit or /debug → bearer can read
traces from any user in `org_a` or `org_b` (resolved via `ECE_USER_ORGS`).

**Use cases**:
- Multi-org manager: `ECE_DELEGATION_ORG_TOKENS="teamlead:org_a,org_b"`
- Auditor / compliance: `ECE_DELEGATION_ORG_TOKENS="audit:*"`
- Department head (single org): `ECE_DELEGATION_ORG_TOKENS="head:org_a"`

Order of checks in /audit and /debug:
1. ADR-004 owner (X-User-Id match)
2. Per-user delegation (cut-018b): X-Delegation-Token in ECE_DELEGATION_TOKENS
3. Per-org delegation (cut-021): X-Delegation-Token in ECE_DELEGATION_ORG_TOKENS
4. X-Org-Id match (cut-019): bearer's org matches trace's org

Steps 2 and 3 grant cross-USER and cross-ORG access respectively, bypassing
step 4. Step 1 always grants access.

**Per-resource delegation (cut-022)**: ✅ wired via `ECE_AUDIT_TOKEN_REQUEST_IDS`.

```bash
export ECE_AUDIT_TOKEN_REQUEST_IDS="audit_tok:req_abc,req_xyz;external:req_def"
```

Format: `token:request_id1,request_id2;token2:request_id3`. Token grants
access to SPECIFIC request_ids only, regardless of who owns them or what
org they're in.

`X-Delegation-Token: audit_tok` on /audit or /debug → bearer can read
`req_abc` and `req_xyz` specifically, no other traces (even from same user).

**Use cases**:
- External auditor given specific case ID: `ECE_AUDIT_TOKEN_REQUEST_IDS="case_2024_q3_xyz:req_001"`
- Customer support lookup for ticket: `ECE_AUDIT_TOKEN_REQUEST_IDS="support_tok:req_abc"`
- Compliance single-trace inspection: `ECE_AUDIT_TOKEN_REQUEST_IDS="compliance_2024_09:req_xyz"`

Step 5 (per-resource): independent of steps 1-3. Token bearer with matching
request_id gets access without needing owner / per-user / per-org grants.
Token without matching request_id falls through to standard X-Org-Id check.

**Org rate limiting (cut-023)**: ✅ wired via `ECE_ORG_RATE_LIMITS`.

```bash
export ECE_ORG_RATE_LIMITS="org_a:100/m;org_b:500/h;org_c:1000/d"
```

Format: `org_id:N/period`. Period is `s|m|h|d` (seconds/minutes/hours/days).
Fixed-window counter per org. After N requests within period, returns `429`
with `Retry-After` header.

Applies to `/audit` + `/debug` only (where X-Org-Id is available). Unconfigured
orgs (no entry in `ECE_ORG_RATE_LIMITS`) are not rate-limited.

**Use cases**:
- Loud neighbor prevention: `ECE_ORG_RATE_LIMITS="org_a:100/m"` to cap one
  org's read traffic at 100/min
- Free tier cap: `ECE_ORG_RATE_LIMITS="free_org:10/h"`
- Burst protection: `ECE_ORG_RATE_LIMITS="org_a:5/s"` for very strict limits

Multi-process deployments: the in-memory bucket is per-process. For shared
state, use Redis (cut-024+). v0.2 keeps it simple (single-process scope).

## 3. X-Org-Id header contract

| Endpoint | Header required (multi-tenant) | Behavior |
|---|---|---|
| `/api/v1/audit/context/{request_id}` | YES (else 400) | X-Org-Id must match trace.org_id (else 403) |
| `/debug/context/{request_id}` | YES (else 400) | Same as /audit |

Errors (multi-tenant mode):
- `400` — `X-Org-Id` header missing
- `403` — `X-Org-Id != trace.org_id` (cross-org blocked)
- Legacy rows (`context_requests.org_id IS NULL`) bypass enforcement
  for v0.1 back-compat

## 4. Multi-tenant perf bench (cut-020)

```bash
# Mock LLM (V0 CI, fast)
uv run python scripts/bench_multi_tenant.py --n 200

# Real LLM (production cut-over verification)
export ECE_LLM_BASE_URL="http://localhost:11434/v1"
export ECE_LLM_API_KEY="EMPTY"
export ECE_LLM_MODEL="qwen2.5:14b"
export ECE_USER_ORGS="alice:org_a;bob:org_b"
uv run python scripts/bench_multi_tenant.py --n 200 --base-url "$ECE_LLM_BASE_URL"
```

**Output**:
- Per-org p50/p95/p99 latency (target: p95 < 1500ms)
- Cross-org /audit denial rate (target: 100%)
- Combined PASS/FAIL

**Exit codes**:
- `0` = perf + multi-tenant verification pass (v0.2 cut-over ready)
- `1` = some gate failed (cut-over blocked; investigate)

## 5. v0.2 cut-over gate (cut-020)


**Exit codes**:
- `0` = E6 ≥80% accuracy AND multi-tenant perf + cross-org denial pass
- `1` = some gate failed (cut-over blocked; investigate)

## 7. Migration from v0.1 to v0.2

1. Apply migration 0007: `uv run alembic upgrade head`
2. Set `ECE_USER_ORGS` env (or keep unset for single-tenant mode)
3. Update /audit + /debug callers to send `X-Org-Id` header
   (mandatory only if `ECE_USER_ORGS` is set)
4. Run multi-tenant bench to verify perf + denial rates
5. Run combined cut-over gate script for final verification

**No-data-loss path**: Pre-cut-019 traces (org_id IS NULL) bypass
enforcement; they remain readable without X-Org-Id. Once all such
traces age out OR are backfilled, multi-tenant enforcement becomes
strict.

## 8. Troubleshooting

| Issue | Check |
|---|---|
| /audit returns 400 | X-User-Id/X-Delegation-Token + X-Org-Id (multi-tenant) |
| /audit returns 403 | X-Org-Id mismatch or non-owner |
| /debug returns 404 | ECE_DEPLOYMENT_MODE=local (not production) |
| /debug returns 403 (IP) | DEBUG_ALLOWED_HOSTS includes your client IP |
| E6 <80% | Check ECE_LLM_BASE_URL reachable; review failing cases |
| Bench p95 > 1.5s | Check DB indexes; consider materializing |
| Bench denial <100% | ECE_USER_ORGS env not set OR trace.org_id NULL |
