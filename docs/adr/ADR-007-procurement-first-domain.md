# ADR-007: Procurement 作为第一个领域包（含合规定位与换域对冲）

- 状态：Accepted（2026-09-04）

## 决策

v0 领域包 = Procurement（采购申请合理性评估），场景锁定 PRD §5（"PR001 这个采购申请合理吗？"）。**产品定位为"建议生成"（Action Level 0/1）**，不做自动审批/自动下单/评标结论。

## 理由

1. 任务-上下文契合度最高：判断合理性天然需要"人+组织+权限+业务对象+历史+政策+时间"全要素，是对引擎五件套的最全覆盖验证。
2. 数据可合成、可演示、可跨行业理解（采购是所有中大型企业的通用职能）。
3. 创始人可达人脉含采购职能（根目录 Round 1 访谈假设），演示后有访谈通道。

## 风险与对冲

- **招投标合规红线**（红队 v1 对 C3 的警告）：产品与话术严格定位"内部申请评估建议"，不输出中标/评标结论，不做价格裁量决策——建议仅供人工审批参考（Level 1）。
- **领域未经访谈裁决**（红队 v3：C1 vs C3 vs Partner 由访谈定）：本 ADR 的领域选择是**工程假设而非商业结论**；对冲 = ADR-010 领域包隔离 + TASKS S6.4 换域演练 + Sprint 0–4 引擎工作全部可复用。

## 后果

若访谈推翻采购方向：换领域包（预计 1–2 周建新 spec/规则/评测），引擎与全部横向测试保留——损失上限可控。
