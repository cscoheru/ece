## 2. Migration

### 2.1 Apply database migrations

```bash
uv run alembic -c src/ece/migrations/alembic.ini upgrade head
```

This applies migration `0007_user_orgs` (adds `org_id` column to
`context_requests`). Backwards-compatible: nullable column, legacy rows
keep `org_id=NULL`.

### 2.2 Verify migration

```sql
SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_name = 'context_requests' AND column_name = 'org_id';
-- Expected: org_id | text | YES
```

### 2.3 Backfill historical rows (cut-024+)

For historical v0.1 traces with `org_id IS NULL`, backfill if known:

```sql
UPDATE context_requests
SET org_id = 'org_legacy'
WHERE org_id IS NULL AND created_at < '2026-09-15';
```

(Adjust org_id per your org mapping.) Without backfill, legacy rows
bypass X-Org-Id check (v0.1 back-compat). For strict enforcement,
backfill + tighten check (cut-025+).

## 4. Header contract for /audit + /debug

| Header | Required | Behavior |
|---|---|---|
| `X-User-Id` | one of these | self access (owner check, irrevocable) |
| `X-Delegation-Token` | one of these | delegation access (revocable) |
| `X-Org-Id` | only if `ECE_USER_ORGS` set | cross-org isolation + rate limit |

Errors:
- `400` missing X-User-Id/X-Delegation-Token OR missing X-Org-Id (multi-tenant)
- `403` non-owner / cross-org / cross-org-token-revoked
- `404` request_id not found
- `429` org rate limit exceeded (Retry-After header)

## 5. Deployment order

1. Apply migration 0007 (`alembic upgrade head`)
2. Set `ECE_USER_ORGS` env (start with empty, then add per-org)
3. Configure `ECE_DELEGATION_TOKENS` for managers / shared services
4. Add `ECE_DELEGATION_ORG_TOKENS` for cross-org access (audit, etc.)
5. Optionally configure `ECE_AUDIT_TOKEN_REQUEST_IDS` for external auditors
6. Set `ECE_ORG_RATE_LIMITS` to prevent loud-neighbor issues
7. Update /audit + /debug callers to send `X-Org-Id` header (mandatory in multi-tenant)
8. Run `bash scripts/verify_v02_rbac.sh` to validate end-to-end
9. Monitor logs for 400 / 403 / 429 responses during first 24 hours

## 6. Rollback plan

If v0.2 causes production issues:

1. **Quick rollback**: unset `ECE_USER_ORGS` env. Multi-tenant mode
   disables, all checks fall back to v0.1 single-tenant behavior.
2. **Token revocation**: add problematic tokens to `ECE_REVOKED_TOKENS`
   without redeployment.
3. **Rate limit adjustment**: lower `ECE_ORG_RATE_LIMITS` numbers.
4. **Migration rollback**: `alembic downgrade -1` reverts migration 0007
   (drops `org_id` column). WARNING: any trace recorded after migration
   0007 will have its org_id column dropped, but the data is recoverable.

## 7. Monitoring

Track these metrics post-cutover:

- `ece_audit_requests_total` (counter by status_code, org_id)
- `ece_audit_403_total` (counter — should be stable, not growing)
- `ece_audit_429_total` (counter — high = need to raise rate limits)
- `ece_token_revocation_hits_total` (counter — non-zero = revoke working)
