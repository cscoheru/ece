# v0.1 Deployment Guide (cut-018b + cut-018c)

This document covers v0.1 deployment hardening (multi-user PermissionScope
+ real LLM ≥80% accuracy gate verification).

## 1. v0.1 deployment features (cut-017 + cut-018)

- **E6 Agent 评测**: 100 questions, ≥80% accuracy required (per EVALUATION.md §1)
- **/audit/context + /debug/context** endpoints: trace inspection (Sprint 6)
- **Audit export CLI** (`scripts/export_audit.py`): bulk export context_requests
  + items to JSON for compliance review
- **/debug IP allowlist** (cut-018a): /debug/* only accessible from
  localhost (127.0.0.1, ::1) to prevent audit trace leakage
- **Multi-user PermissionScope** (cut-018b): managers / shared-services
  can view team's traces via `X-Delegation-Token` header

## 2. Deployment: ECE_DEPLOYMENT_MODE

```bash
export ECE_DEPLOYMENT_MODE=local  # default for development
# or
export ECE_DEPLOYMENT_MODE=production  # hides /debug/* (returns 404)
```

`/debug/*` is hidden in production mode. `/audit/*` (JSON API) remains
available for production audit logging.

## 3. /debug IP allowlist (cut-018a)

```bash
export DEBUG_ALLOWED_HOSTS="127.0.0.1,::1,localhost,testclient"
# or strict:
export DEBUG_ALLOWED_HOSTS="127.0.0.1,::1"  # testclient excluded (for prod)
# or wildcard (internal proxy / load balancer):
export DEBUG_ALLOWED_HOSTS="*"
```

**Production recommendation**:
```bash
export DEBUG_ALLOWED_HOSTS="127.0.0.1,::1"  # strict: only localhost
```

This prevents external access to debug UI even in private deployment.

## 4. Multi-user PermissionScope (cut-018b)

```bash
export ECE_DELEGATION_TOKENS="manager_token:user1_ref,user2_ref;admin_token:user3_ref"
```

Format: `token:user1,user2,user3;token2:user4` — semicolon-separated entries,
each mapping a token to a comma-separated list of user_refs.

`X-Delegation-Token: manager_token` header in `/audit` or `/debug`
request → bearer gets access to user1_ref and user2_ref's traces.

**Use cases**:
- Team lead views team's traces: `ECE_DELEGATION_TOKENS="teamlead:user1,user2,user3"`
- Admin override: `ECE_DELEGATION_TOKENS="admin:user1,user2,user3,user4"`
- Shared service (e.g. compliance audit bot): `ECE_DELEGATION_TOKENS="audit_bot:user1,user2"`

**Multi-user PermissionScope extends ADR-004**: owner can view
their own trace; delegation token bearer can view listed users'
traces. Self + delegation union.

## 5. Real LLM ≥80% accuracy gate (cut-018c)

Per EVALUATION.md §1: E6 Agent runner must hit ≥80% accuracy.
MockLLM is for V0 CI only; real deployment requires real LLM.

### Setup

```bash
# 1. Set LLM endpoint env (any OpenAI-compatible)
export ECE_LLM_BASE_URL="http://localhost:11434/v1"  # Ollama
export ECE_LLM_API_KEY="EMPTY"  # local doesn't need key
export ECE_LLM_MODEL="qwen2.5:14b"  # or gpt-4 / deepseek-chat / etc.

# 2. Optional: ECE_DELEGATION_TOKENS (only for /audit /debug)
# export ECE_DELEGATION_TOKENS="manager:user1,user2"
```

### Verify (cut-018c helper)

```bash
# Helper script invokes E6 runner with --base-url
bash scripts/verify_e6_real_llm.sh
```

**Exit codes**:
- 0 = ≥80% accuracy (v0.1 cut-over ready)
- 1 = <80% accuracy (cut-over blocked; investigate)

**Mock LLM fallback** (no ECE_LLM_BASE_URL): V0 CI only. Production
deployment MUST set the env var for accuracy gate.

## 7. Troubleshooting

| Issue | Check |
|---|---|
| /debug returns 404 | `ECE_DEPLOYMENT_MODE=local` (not production) |
| /debug returns 403 (IP) | `DEBUG_ALLOWED_HOSTS` includes `127.0.0.1` / your client IP |
| /debug returns 403 (user) | Verify `X-User-Id` matches trace.user_ref or use delegation token |
| E6 runner <80% | Check `ECE_LLM_BASE_URL` reachable; review failing cases in output |
| /audit returns 400 | `X-User-Id` or `X-Delegation-Token` required (not both missing) |
